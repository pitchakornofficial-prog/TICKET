## Product goal

เว็บไซต์ขายบัตรคอนเสิร์ตในประเทศไทยที่ลูกค้าซื้อได้โดยไม่สมัครสมาชิก
รองรับผู้จัดงาน/ผู้ว่าจ้างจัดงานนำบัตรมาฝากขาย และมีเจ้าของเว็บกำกับการเปิดขายกับการเงิน
ใช้ชื่อชั่วคราว **TICKET** เว็บเปิดให้ใช้งานต่อเนื่องเมื่อมีงานเพิ่มเข้ามา ไม่ได้กำหนดวันเปิดตัวหรือ SLA ตัวเลข

## Users and agreed scope

| ผู้ใช้ | ขอบเขตที่ยืนยัน |
| --- | --- |
| ลูกค้า | หน้าแรก ค้นหาบัตร ข่าวสาร รายละเอียดคอนเสิร์ต กรอกข้อมูลซื้อบัตร ยืนยันอีเมล ชำระเงิน รับ/เปิดดูบัตรและคำสั่งซื้อ และขอคืนเงินโดยไม่สมัครสมาชิก |
| เจ้าของเว็บ | อนุมัติงาน จัดการข่าวสาร กำหนดค่าบริการและเงินสำรอง ดูยอดขาย อนุมัติคืนเงิน และบันทึกการโอนให้ลูกค้า/ผู้จัดงาน |
| ผู้จัดงาน/ผู้ว่าจ้าง | จัดการงาน รอบการแสดง และประเภทบัตรของตน ส่งอนุมัติ ดูยอดขายและยอดรับเงิน และเพิ่มบัญชีทีมสแกนเฉพาะงาน |
| ทีมสแกนของผู้จัดงาน | สแกนบัตรของงานที่ได้รับสิทธิ์ ทั้งการทำงานออนไลน์และออฟไลน์ตามข้อจำกัดโดเมน |

บทบาททีมสแกนเป็นขอบเขตสิทธิ์ภายใต้ผู้จัดงาน ไม่ขยายเป็นสิทธิ์ owner

## Product capabilities

- ขายบัตรยืน/บัตรเข้างาน หลายประเภท และหลายรอบในหนึ่งคอนเสิร์ต แต่ละรอบแยกจำนวนและเวลาเข้างาน
- Guest checkout พร้อม OTP อีเมลและการกันบัตร ใช้ข้อมูลผู้ซื้อชุดเดียว ออก QR แยกทุกใบ
- รับชำระด้วย QR รายคำสั่งซื้อและผลยืนยันอัตโนมัติ ส่งบัตร/ลิงก์คำสั่งซื้อทางอีเมล
- ค่าบริการทั้งสองฝ่าย เงินสำรอง และการจ่ายรายสัปดาห์ พร้อมการบันทึกหลักฐานโอนโดย owner
- ขอคืนบางใบได้ เจ้าของเว็บอนุมัติและโอนคืน รองรับกรณียกเลิก/เลื่อนงานตามนโยบายที่ยืนยัน
- สแกนบัตรและแสดงสถานะการซิงก์ ภายใต้กติกาเครื่องหลักออฟไลน์หนึ่งเครื่อง
- G-07=B: รองรับออกแล้วกลับเข้างาน โดยบันทึกออกก่อนกลับเข้าใหม่; กติกา admission อยู่ใน CONTEXT.md
- Owner back office (change-scope 2026-10-22, ตาม D-15–D-20): เปิดหน้าภาพรวมที่แสดงจำนวนงานค้างของคิวที่ owner ต้องตัดสินใจอยู่แล้ว และนำทางทุกส่วนงานเดิมผ่านเมนูกลุ่มอนุมัติ/การเงิน/ลูกค้า/ระบบ โดยไม่เพิ่มคิวงาน สิทธิ์ หรือกติกาเงินใหม่

ค่าระยะเวลา 15 นาที, เส้นตายคืนเงิน 7 วัน, รูปแบบค่าบริการ,
การคืนเฉพาะราคาบัตร และกติกาทางการเงิน/ออฟไลน์ฉบับหลักอยู่ใน
[CONTEXT.md](../CONTEXT.md) เพื่อไม่สร้างนโยบายซ้ำสองแห่ง

## Constraints and intended outcomes

- พัฒนาและรันบน **local ก่อน**; deployment และการทดสอบ scaling อยู่ช่วงท้าย ไม่ครอบคลุมการเลื่อน functional verification บน local
- ต้องออกแบบให้รองรับ Horizontal Scaling; เป้าหมายเบื้องต้นประมาณ **200 ผู้ใช้พร้อมกัน** (C4=C) แทนประมาณการเดิม 200 ต่อนาที
- ตัวเลข 200 เป็นเป้าหมาย ไม่ใช่ผล benchmark หรือการรับรอง capacity; workload และเกณฑ์เวลาตอบสนองยังต้องกำหนดก่อนทดสอบ
- เทคโนโลยีที่ยืนยันและเป้าหมาย production อยู่ใน [ADRs](adr/0001-application-and-shared-data.md)
- หน้าเว็บต้องใช้งานได้ตามอุปกรณ์ที่ตกลงใน D-05 และให้ลูกค้าซื้อได้โดยไม่บังคับสมัครสมาชิก
- การเข้าถึงข้อมูลของผู้จัดงาน/ทีมสแกนต้องอยู่ในขอบเขตงานของตนตาม domain context
- G-47=ยืนยัน (Agreed, ผู้ใช้ 2026-10-20): รุ่นแรกใช้ภาษาไทย สกุลเงินบาท (THB) และแสดงวันเวลาตามประเทศไทย `Asia/Bangkok`

## Boundaries

- ไม่เลือกเลขที่นั่ง และไม่บังคับระบุชื่อผู้เข้างานแยกทุกใบ
- เลือก payment QR พร้อมผลอัตโนมัติ ไม่ได้เลือก flow อัปโหลดสลิป
- การโอนจ่ายผู้จัดงานและคืนเงินลูกค้าเป็นงาน manual พร้อมบันทึกหลักฐาน ไม่ได้ตกลง automated disbursement
- ยังไม่ได้ยืนยันหลายภาษา/หลายสกุลเงิน, native mobile app หรือ offline scanning หลายเครื่องอิสระ
- Setup นี้เป็นการบันทึกบริบท ไม่ได้สร้าง feature specification, implementation tasks หรือ implementation
